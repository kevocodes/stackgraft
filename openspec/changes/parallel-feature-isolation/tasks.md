### Decision state

Five items. Items 1 and 2 are decided here and must not be re-decided at implementation. Items 3–5 are carried open, deliberately, with the task that owns each.

1. **DECIDED — slice 4b's acceptance uses a fixture repository carrying a discriminating exec-form healthcheck. The generated read does NOT move forward into 4b.** DS42 leaves this open and forbids discovering it at 4b. Four reasons, in order of weight. **(a) Moving the read forward is circular.** DS42 holds the generated read to DS34's discriminator — so 4b's discriminator must exist before the read can be validated, and the read cannot be 4b's own acceptance evidence for the mechanism that judges it. The fixture breaks that cycle on the correct side. **(b) The fixture is needed either way.** V49's positive — a candidate that *does* discriminate — has no source on the motivating repository (DS42 measured 0 of 4), so a discriminating fixture must be built for 4b whichever way this goes. Moving the read forward does not remove the fixture; it only adds machinery on top of it. **(c) DS37 is one unit and splitting it costs twice.** The read arrives with offer / show / approve / write, the `inferred`-until-observed falsifier and the approval-fingerprint falsifier.
